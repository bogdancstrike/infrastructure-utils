# Upgrading existing installations

The refreshed examples select current releases for new development environments. Changing an image tag does not upgrade stored data, CRDs, certificates, or application schemas. Preserve a backup and follow the component's supported upgrade sequence when reusing an existing installation.

| Component | Configuration change | Existing installation action |
| --- | --- | --- |
| PostgreSQL | Pinned to 18.6; Compose examples explicitly preserve their existing `PGDATA` path | Dump/restore or use the documented `pg_upgrade` procedure across majors. The Docker 18 image changed its default data layout; the examples use an explicit path to retain their named/bind mount layout. The new Kubernetes example mounts `/var/lib/postgresql` with data under `18/docker`. |
| PostgreSQL initialization | Corrected the multi-database scripts to quote SQL identifiers and open separate database connections | These scripts run only on an empty data directory. They no longer put SQL semicolons in psql connection arguments. Existing databases are not changed by editing the scripts. |
| Apache Kafka | Replaced Bitnami with `apache/kafka`, standard `KAFKA_*` settings, and KRaft | The new `kafka-apache-data` volume is deliberately separate from the old Bitnami data volume. Migrate topics/data with supported Kafka tooling; do not rename the old volume to bypass migration. Upgrade existing brokers through supported intermediate versions. |
| Kafka UI | Replaced the old Provectus image with maintained Kafbat | Review authentication and cluster connection settings when carrying over custom configuration. |
| Redpanda | Pinned broker and Console v3; moved Schema Registry configuration to its Console v3 location | Follow the supported broker upgrade sequence. The TLS examples now configure broker listeners explicitly and require client certificates. Replace old example certificates with certificates valid for the actual broker DNS names. |
| Jaeger | Replaced `all-in-one` v1 with Jaeger v2 and an explicit Collector-style configuration | Applications can keep OTLP ports 4317/4318. Legacy 5775, 5778 and 14267 mappings were removed. This example stores traces in memory, so use a persistent backend for retained traces. |
| OpenTelemetry Collector | Added a collector to the tracing stack | Send OTLP to host ports 14317/14318 to pass through the collector, or 4317/4318 for direct Jaeger ingestion. |
| Keycloak | Uses `KC_BOOTSTRAP_ADMIN_USERNAME` / `KC_BOOTSTRAP_ADMIN_PASSWORD` | Bootstrap values initialize a new administrator; they do not reset an existing account. Apply the Keycloak migration guide and export/back up existing realms first. The example uses `start-dev`; production needs a supported external database, hostname, and TLS configuration. |
| MySQL | Uses the 8.4 LTS line; removed `--default-authentication-plugin=mysql_native_password` | Update clients for `caching_sha2_password`. Upgrade supported data versions explicitly; use the supported upgrade path for an existing 8.0/8.2 data directory. |
| InfluxDB | Stays on 2.x for Flux compatibility; uses `DOCKER_INFLUXDB_INIT_*` settings and persistent config/data volumes | Old `INFLUXDB_DB` initialization settings belong to InfluxDB 1.x. The new example uses named volumes instead of host-specific `/data` and TLS paths; explicitly migrate old data into these volumes. Initialization runs only on an empty database. |
| Elasticsearch stack | All Elastic components pinned to the same 9.5.5 release; missing pipelines supplied | Follow Elastic's supported 8.x-to-9.x upgrade path and reindex incompatible indices. The examples disable authentication for local development. |
| EventStoreDB / KurrentDB | Uses KurrentDB's publisher image and `KURRENTDB_*` settings; removed old TCP/AtomPub flags | Follow KurrentDB's version migration sequence. Existing EventStore volume data is retained, while container paths are updated to `/var/lib/kurrentdb` and `/var/log/kurrentdb`. Use current gRPC clients on port 2113. |
| GitLab | CE and Runner pinned; explicit persistent config, log and data volumes | Follow GitLab's required upgrade stops. The new volume mounts replace previously ephemeral container storage; back up the original instance before recreating it. |
| Gitea / MariaDB / MongoDB / MySQL | Added missing persistent data mounts | Export any data that was stored in a container's writable layer before recreating it. New volumes are initially empty. |
| RedisInsight | Corrected its persistent path to `/data` | Copy any useful contents from an old `/db` volume into the new expected layout. |
| MinIO | Old registry image is unavailable; optional local build uses the frozen final upstream source tag | Prefer SeaweedFS for new setups. Copy existing objects using S3 clients such as rclone; storage formats are not interchangeable. This source build has been statically validated, not built or started as part of the refresh. |
| Mailserver / InfluxDB / Gammu | Corrected examples that were previously named `Dockerfile` but contained Compose YAML | Use their `docker-compose.yml` files. Gammu now has a real Dockerfile and a separate modem configuration. |

The original site-specific Kubernetes overrides remain in their version-named directories. They include private hostnames, addresses, storage settings and appliance configuration. They have not been blindly applied to the new charts: port the settings needed by your environment into the matching `k8s/values` files and validate the rendered result. The [Kubernetes migration map](../k8s/README.md#original-chart-migration-map) lists replacements and retained references.

Sources: [PostgreSQL Docker data layout](https://hub.docker.com/_/postgres), [Keycloak container configuration](https://www.keycloak.org/server/containers), [GitLab upgrade paths](https://docs.gitlab.com/update/upgrade_paths/), [MySQL upgrade paths](https://dev.mysql.com/doc/refman/8.4/en/upgrade-paths.html), [Jaeger v2 configuration](https://www.jaegertracing.io/docs/latest/configuration/).
